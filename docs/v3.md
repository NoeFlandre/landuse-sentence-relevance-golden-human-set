# V3 workflow (paused)

V3 extends the human set from 154 adjudicated V2 rows to 300 rows across three
sources. The work is **paused**: no V3 benchmark is published, and the benchmark
to use remains `data/benchmark/v2-adjudicated.csv`. This page records the agreed
V3 workflow so the public documentation matches the paused state.

## Upstream datasets

V3 streams three public Hugging Face datasets. Revisions are pinned by commit
SHA in `src/landuse_sentence_relevance/config.py`, and no upstream dataset is
ever materialized locally.

| Source | Dataset | Records used |
| --- | --- | --- |
| Description tag | [OSM polygon description tag](https://huggingface.co/datasets/NoeFlandre/osm-polygon-description-tag) | `language-v1` sentence records with `language_code` and `sentences` |
| Wikipedia | [OSM polygon Wikidata and Wikipedia](https://huggingface.co/datasets/NoeFlandre/osm-polygon-wikidata-and-wikipedia) | `wikipedia_sentences` records with `language`, `project`, and `section_index` |
| Website tag | [OSM polygon website tag](https://huggingface.co/datasets/NoeFlandre/osm-polygon-website-tag) | `website_sentences` and `contact_website_sentences` with their `*_language` fields |

### Sentence and language contract

Every V3 source already publishes sentence-level records and upstream language
metadata, so V3 consumes them as they are:

- Sentences come from the upstream sentence fields. **No local splitter runs**:
  SaT-12L-sm is not used for V3.
- English filtering uses upstream language metadata only. **No local language
  model runs**: CommonLingua is not used for V3.
- Wikipedia rows are restricted to `project=wikipedia` and English articles.
  **Wikivoyage is excluded**: the `wikivoyage_sentences` and
  `wikivoyage_sections` configurations are never read.
- Wikipedia selection stays contextual: title-only and lead-only sentences are
  rejected, as in V2.
- Where sentence records carry no coordinates, geolocation is resolved with
  bounded streaming joins back to the polygon records, so provenance stays
  deterministic.

## Candidate pool and geographic preflight

- At least 400 fresh candidates per source by default, one candidate per
  globally unique H3 resolution-3 cell.
- Every H3 cell already occupied by a V2 row is reserved, so V3 additions never
  collide with the frozen benchmark.
- Selection is deterministic and spread across the world.
- A preflight check verifies that enough candidates and distinct cells exist for
  the V3 quotas before the annotation UI starts.
- Only compact candidate metadata and checkpoints are written to the Seagate
  project drive; upstream rows are streamed and discarded.

## V2 reuse and quota arithmetic

`data/benchmark/v2-adjudicated.csv` is immutable and is never edited. V3 seeds
its state from that file and annotates only the remaining rows.

| Source | Seeded from V2 | New annotations | V3 total (yes / no) |
| --- | --- | --- | --- |
| Wikipedia | 99 | 1 | 100 (50 / 50) |
| Website | 54 | 46 | 100 (50 / 50) |
| Description | 0 | 100 | 100 (50 / 50) |
| **Total** | **153** | **147** | **300** |

V2 holds 100 Wikipedia rows (49 yes, 51 no) and 54 website rows (31 yes, 23 no).
V3 reuses 99 Wikipedia rows — one surplus `no` row is left out of the V3 quota —
and adds a single Wikipedia `yes` row to reach 50 / 50. All 54 website rows are
reused, so 46 new website rows close the per-label gap, and the description
source contributes 100 entirely new rows. Seeded V2 rows count toward the
progress metrics but are never presented for reannotation.

## Storage and resume behavior

V3 keeps its own files beside the V2 ones on the Seagate project drive, mirroring
the V2 layout under a `v3` prefix:

| Artifact | Path |
| --- | --- |
| Candidate pool | `results/candidates/v3/pool.json` |
| Candidate progress checkpoint | `results/candidates/v3/progress.json` |
| Annotation session | `results/annotations/sessions/v3.jsonl` |
| Runtime and auth state | `state/runtime-cache`, `state/huggingface-auth` |

No V3 path overwrites V2 state. Candidate building checkpoints after each pass
and resumes with only the remaining cell quota, so an interrupted run does not
repeat completed source work. The annotation session is appended atomically, so
labeling, relabeling, removing a row, quitting, and resuming behave exactly as
in V2. The UI shows total and per-source progress, yes/no counts, and the
remaining quotas, and it starts only after the candidate preflight succeeds.

## Limitations

- V3 is paused and incomplete. No V3 split is published, and no `v3` benchmark
  file exists under `data/benchmark/`.
- V3 changes nothing about V2: the released `v2` artifacts, splits, and tags are
  frozen, and the [versioning policy](versioning.md) still applies.
- V3 inherits upstream sentence segmentation and language labels, so upstream
  segmentation or language errors are not corrected locally.
- Coverage is one sentence per H3 resolution-3 cell, which bounds geographic
  density rather than guaranteeing balanced regional representation.
- The description source is new in V3 and has no V2 rows to reuse, so it depends
  entirely on fresh annotation.
